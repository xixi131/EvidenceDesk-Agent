# 12｜语料审阅与清洗规则

> 本文定义 GitHub Actions 原始语料如何进入第一次中文 RAG Baseline，以及未来 Cleaner 可以做什么、不能做什么。当前阶段只完成数据画像、选择规则和清洗设计，尚未实现 Cleaner，也没有生成 Cleaned 文档、Chunk、Embedding 或 Weaviate 索引。

- 状态：Accepted
- 决策日期：2026-08-05
- Source Dataset：`github-actions-zh-2026-08-05-v1`
- Baseline Dataset：`github-actions-zh-baseline-v1`
- Cleaning Rules：`github-actions-cleaning-v1`

## 1. 三层数据必须分开

```text
Source Manifest + Raw Documents
记录官方原始快照，不能被实验修改

Baseline Manifest
记录第一次实验选择哪些文档，以及每篇文档的风险

Cleaned Documents
未来根据固定清洗规则生成的派生副本
```

本地对应关系：

```text
data/knowledge_base/github_actions_zh_v1/
├── manifest.json                 # 原始数据收货单
├── baseline_manifest.json        # 第一次实验领料单
├── documents/                    # 33 篇 Raw 原始文档
├── cleaned/                      # Cleaner 实现后生成，当前不存在
└── reports/
    └── corpus_profile.json       # 数据画像汇总
```

`documents/` 是 Raw 数据目录。为了避免无意义地移动已经固定并校验哈希的文件，第一版保留该名称，不重命名为 `raw/`。

## 3. 第一次 Baseline 的文档范围

第一次中文 RAG Baseline 纳入 29 篇，暂不纳入以下 4 篇英文占主导的参考文档：

```text
GitHub Actions 的工作流语法
工作流运行的 REST API 终结点
工作流作业的 REST API 终结点
工作流的 REST API 终结点
```

这 4 篇仍保留在 Raw 数据中，不删除、不归档，也不判定为低质量。它们记录为：

```text
baseline_included=false
future_experiment=github-actions-multilingual-reference-v1
```

原因：

- 4 篇文档占原始语料字符量约 70%；
- 正文以英文为主；
- 最大文档同时包含 216 个标题和 135 个代码块；
- 第一次 Baseline 使用中文轻量 Embedding；
- 混入后会同时改变语言、数据量、文档结构和模型适配难度，无法判断失败原因。

后续多语言实验再固定其他参数，比较是否加入这 4 篇以及是否更换 `bge-m3`。

## 4. Baseline Manifest 的职责

文件：

```text
data/knowledge_base/github_actions_zh_v1/baseline_manifest.json
```

它不会复制原始正文，只记录每篇文档在第一次实验中的状态：

```text
document_id
title
category
source_relative_path
source_url
source_sha256
language_profile
baseline_included
exclusion_reason
future_experiment
cleaning_status
risk_flags
metrics
```

关键字段：

- `source_sha256`：证明处理的是哪份 Raw 文件；
- `baseline_included`：控制第一次导入是否选择该文档；
- `risk_flags`：提示 Cleaner 和人工抽查重点；
- `cleaning_status`：当前为 `pending`，Cleaner 完成后才能变成 `completed`；
- `future_experiment`：记录暂时排除的文档以后在哪个实验重新加入。

## 5. 风险标记的含义

当前风险标记包括：

```text
english_dominant              英文正文占主导
mixed_language_or_code_heavy  中英文、URL、标识符或代码较多
large_document                10,000 字符以上
oversized_document            50,000 字符以上
many_code_blocks              20 个以上代码块
inline_svg                    包含内联 SVG
inline_html                   包含 HTML 标签
relative_links                包含 /zh 或 /en 相对链接
english_relative_links        包含指向英文页面的相对链接
escaped_callouts              包含 \[!NOTE] 等标记
```

风险标记不是错误，也不会自动删除文档。它表示：

> 这篇文档在清洗、分块或抽查时需要特别关注。

## 6. Cleaner 的输入和输出

未来 Cleaner 输入：

```text
baseline_manifest.json 中 baseline_included=true 的 29 篇 Raw 文档
```

输出目录：

```text
data/knowledge_base/github_actions_zh_v1/cleaned/
```

每个 Cleaned 文档必须能够追溯到：

```text
source_dataset_version
source_document_id
source_sha256
cleaning_rules_version
cleaned_sha256
```

Cleaner 不能覆盖 `documents/` 中的 Raw 文件。

## 7. 第一版清洗规则

### 7.1 统一文本基础格式

允许：

- 使用 UTF-8；
- 将 CRLF 统一为 LF；
- 删除行尾空格；
- 将连续三个以上空行压缩为两个；
- 保留正常段落空行。

禁止：

- 改写官方句子；
- 自动总结；
- 自动翻译；
- 合并含义不同的段落。

### 7.2 SVG 和 HTML

正文中的内联 SVG 通常只是按钮或图标。

处理原则：

```text
有 aria-label 或可读名称
→ 用名称替代 SVG

没有可读名称
→ 删除 SVG 图形代码
```

普通 HTML 标签删除标签但保留可见正文。

代码围栏内部的 HTML、XML、SVG 示例不做上述清洗，因为它们可能是用户需要检索的代码知识。

### 7.3 链接

将：

```text
/zh/actions/...
/en/actions/...
```

转换为：

```text
https://docs.github.com/zh/actions/...
https://docs.github.com/en/actions/...
```

保留：

- 链接显示文本；
- `#anchor`；
- 外部完整 URL。

这样 Citation 返回给用户时可以直接访问原始页面。

### 7.4 Callout

将展示标记：

```text
\[!NOTE]
\[!WARNING]
\[!CAUTION]
\[!IMPORTANT]
```

规范化为可读文字：

```text
注意：
警告：
谨慎：
重要：
```

不能删除 Callout 正文，因为其中可能包含权限、安全和版本限制。

### 7.5 标题和章节

必须保留：

```text
H1
H2
H3
必要的 H4-H6
```

Cleaner 不负责最终分块，但必须输出稳定的标题结构，供后续 Structure Extractor 生成 `section_path`。

### 7.6 代码块和 YAML

必须保留：

- 代码围栏；
- 语言标记；
- YAML Key；
- Shell 命令；
- 环境变量；
- API 路径；
- 参数名和示例值。

Cleaner 不能为了减少字符数删除代码。代码是否过长、如何分块，由后续 Splitter 决定。

## 8. 清洗报告

Cleaner 完成后必须生成：

```text
data/knowledge_base/github_actions_zh_v1/reports/cleaning_report.json
```

至少记录：

```text
输入文档数
输出文档数
每篇 source_sha256
每篇 cleaned_sha256
删除 SVG 数量
替换 SVG 标签数量
删除 HTML 标签数量
转换链接数量
转换 Callout 数量
警告和失败
```

没有报告，就无法判断 Cleaner 是否意外删除了大量知识。

## 9. 人工抽查

第一版至少抽查三类文档：

```text
小型文档：启用调试日志记录
中型文档：故障排除工作流
大型文档：将标签与自托管运行程序结合使用
```

每篇对比 Raw 和 Cleaned：

- 标题是否保留；
- 正文含义是否改变；
- 代码块是否完整；
- 链接是否可访问；
- SVG 噪声是否删除；
- NOTE/WARNING 正文是否保留。
