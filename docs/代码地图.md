# 代码地图｜一屏看懂 RAG 数据处理

> 一晕就看这页。核心只有一句话：**一条流水线，原料从头进、成品从尾出。**
> 二十来个文件不是二十个平级的东西，它们只有 **4 种角色**，排成 **一条直线**。
> 最后更新：2026-08-13（对应阶段 1A/1B 完成、1C 未开始）

## 一、流水线：一份文档如何变成 Chunk

```
manifest.json          ← 清单：这批要处理哪 29 篇
      │  manifest.py（读 + 校验 33/29/4、唯一 ID、SHA-256）
      ▼
原始 .md (documents/)   ← 原料（33 篇 Raw，其中 29 篇进 Baseline）
      │  markdown_loader.py   → 产出 ParsedDocument（原文 + 来源信息）
      ▼
      │  cleaner.py           → 产出 CleaningResult（去 SVG/HTML、修链接、转 Callout）
      ▼
cleaned/*.md            ← 半成品（29 篇干净 md）
      ▲  ↑ 上面这段由 cleaning_pipeline.py 跑完并存盘：cleaned/ + reports/cleaning_report.json
      │
      │  section_extractor.py → 产出 Section（按标题切成一段段，带标题路径）
      ▼
      │  strategies.py + splitter.py → 结构优先 + 递归，把每段切成 ~600 字 / 重叠 80
      ▼
      │  chunk_builder.py     → 产出 Chunk（带确定性 id、来源 URL、各版本号）
      ▼
293 个 Chunk            ← 成品
      ▲  ↑ 上面这段由 chunk_quality_pipeline.py 跑完并存盘：reports/chunk_report_600_80.json
      │
      ▼
【下一步 · 阶段 1C】embedding → 写 Weaviate → top_k 检索 → 带引用回答   ← 还没做，就是要接的那一截
```

数据形态在管线上的变化（②加工站把上一种“名词”变成下一种）：

```
清单条目 → ParsedDocument → CleaningResult →（存盘 cleaned/*.md）→ Section → Chunk
```

## 二、4 种角色：看到一个文件，先问它是哪一种

| 角色 | 是什么（一句话） | 对应文件 |
|---|---|---|
| **① 流动的数据**（`rag/models/`） | 在管线上传递的“东西”，每站换一种形态；是**名词** | `source.py`（清单：SourceDocument / SourceManifest / BaselineManifest）· `cleaning.py`（ParsedDocument / CleaningResult / 各类 Report）· `section.py`（Section）· `chunk.py`（Chunk + chunk_id 生成）· `chunk_quality.py`（质量报告结构） |
| **② 加工站** | 每个只干一件事，输入一种形态、输出下一种；是**动词** | 清洗段：`corpus/manifest.py` · `corpus/markdown_loader.py` · `corpus/cleaner.py`　切块段：`chunking/section_extractor.py` · `chunking/strategies.py` · `chunking/splitter.py` · `chunking/chunk_builder.py` |
| **③ 流水线** | 把几个加工站**串起来跑一遍并存盘**；是**动词连成句** | `corpus/cleaning_pipeline.py`（跑完清洗段）· `chunking/chunk_quality_pipeline.py`（跑完切块段） |
| **④ 旁路工具** | 不在主线上，只是**看 / 统计**成品 | `chunking/quality_report.py`（统计 chunk 长度、短块、重复）· `chunking/chunk_inspector.py` + `scripts/inspect_chunk.py`（按 id 抽查单条）· `chunking/contracts.py`（接口约定） |

记住这张表，就不用背 20 个文件名：
- **①名词、②动词、③把动词连起来、④拿放大镜看成品。**
- 迷路时，先定位“我现在在哪一站”，再看它的输入形态和输出形态。

## 三、怎么用这张地图学习：别读文件，追一份数据

规矩步骤是给交付用的；**学习要反过来——盯住一份真实数据，看它在每一站变成什么样。**

推荐练习：挑 1 篇文档，把它在四站的样子依次打印出来——

```
原始 .md  →  清洗后（去掉了什么）  →  切成哪几个 Section  →  变成哪几个 Chunk
```

跑通这一遍，你对 RAG 的“数据处理”就通了，比读任何计划都快。相关入口：
- 看单个成品 Chunk：`python scripts/inspect_chunk.py <chunk_id>`
- 重跑清洗段：`generate_cleaned_corpus(corpus_root)`（`corpus/cleaning_pipeline.py`）
- 重跑切块段：`generate_chunk_quality_report(corpus_root)`（`chunking/chunk_quality_pipeline.py`）
