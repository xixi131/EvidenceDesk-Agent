# 08｜工程规范与问题排查

## 1. 配置管理

使用 Pydantic Settings 集中读取：

```text
APP_ENV
DATABASE_URL
WEAVIATE_URL
LLM_MODEL
OPENAI_BASE_URL
EMBEDDING_MODEL
RETRIEVAL_TOP_K
LANGSMITH_PROJECT
GITHUB_TOKEN
GITHUB_API_BASE_URL
GITHUB_API_VERSION
GITHUB_DEMO_OWNER
GITHUB_DEMO_REPO
```

规则：

- 业务代码不直接调用 `os.getenv`；
- `.env` 不提交；
- `.env.example` 写全字段但不放真实值；
- `GITHUB_API_BASE_URL` 默认 `https://api.github.com`；
- `GITHUB_API_VERSION` 固定为 `2026-03-10`，升级前查官方变更并运行 Tool 回归；
- 配置启动时校验；
- 实验参数写入配置快照。

### 1.1 模块边界和目录深度

- `api` 只能依赖 `application`、API Schema 和 `core`，不能直接创建外部 Client；
- `application` 不导入 FastAPI，不生成 HTTP Response；
- `infrastructure` 只实现外部 I/O，不决定 Agent 路由和回答策略；
- `main.py` 负责组装 Application Service 与真实 Adapter；
- 默认最多一层子包；出现多个稳定实现或超过约 15 个高耦合文件后再拆；
- 新增目录前先回答“它隔离了什么变化”，不能只因为名称听起来专业就分层；
- 测试通过 Fake 或注入的 Callable 替换外部实现，不让 Unit Test 连接真实服务。

## 2. 日志

每个请求至少包含：

```text
request_id
thread_id
route
node
retrieved_doc_ids
tool_name
latency_ms
status
error_code
```

不要默认记录：

- API Key；
- 完整系统提示词；
- 完整敏感文档；
- 用户隐私；
- 数据库密码。

## 4. 测试金字塔

### Unit

- Chunk Splitter；
- 指标公式；
- Route 函数；
- Pydantic Schema；
- Tool 参数；
- Citation。

### Integration

- FastAPI + PostgreSQL；
- FastAPI + Weaviate；
- GitHub Gateway + Fake HTTP/真实公开仓库只读调用；
- Repository；
- 33 篇 Source 数据校验 + 29 篇 Baseline 文档导入；
- Checkpointer 恢复。

### Graph

使用 Fake Model/Fake Tool 验证：

- Node 顺序；
- 分支；
- 循环上限；
- interrupt；
- 错误回退。

### Evaluation Regression

使用 10～20 条轻量集，防止：

- Recall 明显下降；
- 路由退化；
- 无答案开始编造；
- Tool 参数错误。

## 5. Mock/Fake 原则

Unit Test 不调用真实模型。

Fake 应返回可预测结果：

```text
输入 A → route knowledge
输入 B → 调用 get_workflow_run
输入 C → evidence insufficient
```

真实 API 验证放到单独的集成/手动测试，避免 CI 不稳定和费用失控。

## 6. 数据库规范

- 所有表由 Alembic 管理；
- 一个请求一个事务边界；
- Repository 不 commit，由 Unit of Work/Service 决定；
- 写操作支持幂等；
- Migration 必须可在空库运行；
- 测试不能连接开发库。

## 7. Weaviate 规范

- Collection Schema 版本化；
- Embedding 模型名和维度记录；
- parent_doc_id 必填；
- status/version 可过滤；
- 更换模型创建新 Collection 或全量重建；
- 索引前后数量核对；
- Upsert 失败需要任务状态。

## 8. Prompt 管理

Prompt 不散落在 Node 中。

每个 Prompt 保存：

```text
name
version
purpose
inputs
output_schema
content
examples
change_reason
```

Prompt 修改必须跑固定评测集。

## 9. CI

Pull Request 至少运行：

```bash
ruff check .
ruff format --check .
mypy src
pytest tests/unit
pytest tests/evaluation -m smoke
```

集成测试可以使用独立 Job 启动 PostgreSQL/Weaviate。

## 10. Docker Compose

服务：

```text
api
postgres
weaviate
```

要求：

- healthcheck；
- depends_on 不代替 ready 检查；
- Volume 持久化；
- Secret 不写镜像；
- API 容器启动时执行 Migration 或独立 migration Job；
- 模型下载策略明确。

## 11. 安全

### Prompt Injection

检索文档视为数据，不是系统指令。

### Tool 权限

```text
只读 Tool：可自动
写 Tool：审批 + 幂等 + 审计
```

### 数据过滤

权限过滤应在检索层完成，不能检索全部后让模型“不要泄露”。第一版虽不做多租户，也要在 Schema 预留 knowledge_base_id/status。

### 冻结语料

- Source 校验读取 `manifest.json`，Baseline 导入读取 `baseline_manifest.json`；
- 导入前校验文档数量和 SHA-256；
- 同一个 dataset_version 不允许静默覆盖内容；
- 引用必须保留原始 GitHub Docs 页面 URL。

### 文件上传

后续开放上传时限制：

- 类型；
- 大小；
- 文件名；
- 路径；
- 解析超时。

## 12. 排错顺序

### 系统起不来

```text
虚拟环境
→ 配置
→ PostgreSQL
→ Weaviate
→ 模型服务
→ 第一个真实异常
```

### 检索为空

```text
文档登记
→ Chunk 数量
→ 向量数量
→ Collection
→ 维度
→ filter
→ query
```

### 检索不相关

```text
Ground Truth
→ Chunk
→ title/metadata
→ Embedding Instruction
→ BM25/Hybrid
→ top_k
→ Reranker
```

### 检索正确但回答错

```text
Context 是否进入 Prompt
→ 是否混入旧版本
→ Prompt 证据约束
→ 模型输出
→ Citation
```

### Agent 走错分支

```text
输入实体
→ 分类 Schema
→ 规则优先
→ LLM 输出
→ State 写入
→ Conditional Edge
```

### GitHub Tool 失败

```text
owner/repo/run_id 校验
→ 网络和超时
→ Token 是否存在
→ 认证/权限
→ API 限流
→ 资源是否存在
→ GitHub request id
```

### Tool 重复执行

```text
Graph 重试
→ idempotency_key
→ action_id
→ Checkpoint 恢复
→ 数据库唯一约束
```

## 13. 完成一次修复的标准

不是“改完能跑”，而是：

1. 复现问题；
2. 找到第一根因；
3. 修改最小范围；
4. 添加测试；
5. 跑相关评测；
6. 检查没有退化；
7. 记录原因和决定。
